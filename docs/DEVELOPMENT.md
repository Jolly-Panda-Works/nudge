# Development

## Toolchain
Flutter 3.35.0 (stable, Dart 3.9), JDK 17, Android SDK; Visual Studio 2022 (C++ desktop workload) for Windows. The version is pinned in `pubspec.yaml` and every workflow.

## Local commands
```bash
flutter pub get
dart run build_runner build
dart format .
flutter analyze --no-fatal-infos   # same as CI
flutter test
```

## Working without a local Flutter installation
All steps run on GitHub Actions, so a browser and git are enough:

1. Push to `main`.
2. **Format code** runs automatically and commits formatting changes, then starts CI on that commit.
3. **CI** generates the platform folders if they are missing, then builds the Android release APKs and the Windows release, runs analysis and tests in parallel, and publishes a GitHub release for the commit. On any other branch the outputs stay in the run's artifacts, named with the branch and commit, so experiments never touch `main` or the releases.
4. When something fails, open the failed step in the Actions run; the log is what maintainers need.

## Platform folders (`android/`, `windows/`)
These folders are generated by `flutter create`, so they do not have to be committed. Before each build, CI checks whether the project exists; if it does not, it runs `flutter create . --platforms=<android|windows> --project-name nudge --org com.jollypanda`, and then runs `tools/wire_capture.py`. That script (idempotent) registers the capture, export and reminder channels in `MainActivity.kt`, declares the notification listener service, the `<queries>` entry, the share target, the reminder permissions and the reminder receivers in `AndroidManifest.xml`, sets the application id and release signing in `build.gradle.kts`, and sets the display name to "Nudge" on both platforms. The Kotlin sources in `android/app/src/main/kotlin/app/nudge/capture/` are committed.

If you want to open the project in Android Studio or run it locally, generate the folders yourself and wire them:
```bash
flutter create . --platforms=android,windows --project-name nudge --org com.jollypanda
python3 tools/wire_capture.py
```

## Applying a delivered zip
From version 0.10.0 a zip contains only the files that changed since the previous delivery, plus `CHANGED_FILES.txt` (the list) and `GIT_COMMIT.txt`. Copy it over the repository, keeping the folder structure; nothing is deleted unless `CHANGED_FILES.txt` says "deleted". The rest of this section describes the older whole-project zips.

Delivered zips contain the whole project except the generated `android/` and `windows/` folders (apart from the committed Kotlin sources). Replacing the repository contents with a zip is therefore safe: CI regenerates the platform folders. Files that no longer exist in the zip are deleted by that replacement, which is how obsolete files disappear. If you only copy the zip over the repository instead, delete such files manually; the release notes of each zip list them.

## Workflows
| Workflow | Trigger | What it does |
|---|---|---|
| CI | push to any branch, version tags (`v*`), PRs from forks, manual | decides the version; in parallel: analyze and tests, the Android debug APK, the Windows build; `main` and `v*` tags publish a GitHub release (see [RELEASING.md](RELEASING.md)) |
| Format code | push to `main`, manual | `dart format`, commits (formatting only, so no extra build) |

Commits made by workflows with `GITHUB_TOKEN` do not trigger other workflows. The Format workflow relies on that on purpose: its commit only changes formatting, so it does not start another build.

## Versioning and outputs
The version is in `pubspec.yaml` and `lib/app_info.dart` (a test keeps them equal). Build outputs carry it in the file name: `Nudge_v<version>_android-debug.apk`, `Nudge_v<version>_windows-x64.zip`. Every push to `main` creates a release; named versions come from `vX.Y.Z` tags.

## Trying notification capture on a phone
Capture works only on Android.

1. Install the APK from the latest release.
2. On Android 13 and later, a sideloaded app cannot be given Notification Access until you allow restricted settings: open Settings > Apps > Nudge, open the three-dot menu and choose **Allow restricted settings**.
3. Open Nudge and tap **Open Notification Access settings**, then enable Nudge.
4. Return to the app. The status screen should show access granted and the listener connected.
5. Trigger a notification from another app. It appears in the inbox. Tap it to see the details.
6. Dismiss the notification on the phone. It disappears from **Active** and shows as *Dismissed* under **All**.
7. Open Settings: access and listener state, capture mode, the app filter and the two toggles should reflect what you choose. Try "Only selected apps" with one app selected and confirm other apps stop appearing.
8. Turn Notification Access off in the system settings and return to Nudge: the banner "Notification access is off" should appear.

If something does not match, note the Android version, the device manufacturer and what the status screen shows, and open an issue (without real notification content).

## Trying import, export and deletion on a phone
1. **Share target:** in another app, select some text, tap Share and choose Nudge. Open Nudge: the text should appear in the inbox under the source "Shared" (open the details to see "Shared or imported text"). Sharing while Nudge is already open should add it without restarting.
2. **Import button:** tap the plus button in the inbox, enter some text and import it.
3. **Export:** Settings > Export data > Export. The system file picker should open; save the file, then open it in a text viewer and check that it is valid JSON with your notifications.
4. **Delete one:** open a notification, tap the trash icon and confirm.
5. **Retention:** Settings > Keep notifications for > choose a period. Notifications older than that disappear.
6. **Delete all:** Settings > Delete all notifications > confirm; the inbox is empty and the counts show 0.

## Trying reminders on a phone
1. Create a reminder for 2 minutes ahead (Create reminder from a notification, or the + button on Tasks) and allow notifications when asked. The alert should appear on time with a Snooze 10 min button.
2. Tap Snooze: it should alert again 10 minutes later, and after opening the app the task should show the snoozed time.
3. Repeat with the app swiped away from recents, and after restarting the phone with a reminder set for later (it should still alert; one that came due while the phone was off should appear after start-up).
4. Settings > Reminders: after you turn notifications off for Nudge it should say "Blocked" and open the right system screen. On Android 14 exact timing is "Not allowed" until you allow it; then reminders should arrive within seconds of the chosen time.
5. Mark a task done, archive it or delete it before its time: no alert should appear.

## Trying device calendars on a phone
1. Settings > Calendars: the switch is off and no permission was asked. Turn it on: the system dialog appears; allow it.
2. The calendars of your accounts (Google, Samsung...) are listed by account with their colours; read-only ones (holidays, subscribed) are marked. Compare with the phone's own calendar app.
3. Hide one calendar, leave the screen and return: the choice is kept. Choose the calendar for new events; a read-only one is not offered.
4. Turn the switch off: the list disappears. Refuse the permission once: the screen says so and "Open settings" opens the app's system settings. Take the permission away while the integration is on: a warning appears.
5. Report: Android version, phone brand, which account types appeared, and anything missing compared with the calendar app.
6. With the integration on, open Calendar: the events of the shown calendars appear on their days (compare with the phone's calendar app), recurring events on every occurrence, all-day events in the "All day" block of the day view, events over midnight on both days. Tasks stay round dots, events are squares in the calendar's colour. Tap an event: "Open in calendar app" opens it. Hide a calendar in Settings > Calendars: its events disappear after returning.
7. Create an event with the `+` button on the Calendar screen (New event): it should appear in the phone's own calendar app within seconds, in the calendar you chose, and sync to the account. Edit its title and time, then delete it; check the same in the calendar app. Try an all-day event and one over midnight.
8. Open a repeating event and an event of a read-only calendar (holidays): no Edit or Delete, only "Open in calendar app".
9. Open a task with a date and time and tap Add to calendar: an event appears in the default calendar. Open the task again: it says "In your calendar". Delete that event in the calendar app and reopen the task: you can add it again. Report what you see with the Android version, brand and account type.
